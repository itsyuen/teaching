## 二、重點觀念整理

### 1. 感測器的基本工作原理

感測器的核心功能是將外界的物理量、化學量或生物訊號轉換成可供系統處理的電氣訊號或數位資料。常見物理量包括：

- 溫度
- 濕度
- 光線
- 壓力
- 距離
- 加速度
- 角速度
- 磁場
- 氣體濃度
- 聲音與振動

典型流程可理解為：

```text
檢測對象 → 感測元件 → 訊號調理/增幅 → A/D 轉換 → 數位資料 → MCU/平台處理
```

---

### 2. 物聯網三層架構

常見 IoT 架構可分成：

| 層級 | 功能 |
|---|---|
| 感知層 | 感測、辨識、資料收集，例如感測器、RFID、GPS、Beacon |
| 網路層 | 將資料傳輸到平台，例如 Wi-Fi、4G/5G、Bluetooth、MQTT、CoAP |
| 應用層 | 資料分析、決策、服務，例如智慧家庭、健康照護、車聯網、智慧農業 |

---

### 3. 常見感測器與典型用途

| 感測器 | 典型用途 |

| LiDAR | 距離、深度、障礙物輪廓、SLAM |

## 三、車聯網與自駕車感測器重點

自駕車常見感測器包含：

- Camera：類似人類視覺，可辨識車道、交通號誌、行人、車輛，但受光線、雨霧、夜間環境影響。
- LiDAR：透過雷射飛行時間取得距離與深度資訊，適合建立周遭 3D 環境。
- Radar：毫米波雷達對雨霧環境較穩定，常用於車距、盲點、自動跟車。
- Ultrasonic：短距離偵測，常用於停車輔助與倒車雷達。
- IMU：GPS 不穩或進入隧道時，可輔助估測車輛運動狀態。

## 四、工程除錯觀念

題庫多次出現「感測器異常時如何處理」的情境。可以整理成工程判斷順序：

1. 先看原始感測數據是否合理。
2. 檢查供電與接地是否正確。
3. 檢查 GPIO / ADC / I2C / SPI / UART 腳位設定。
4. 重新啟動單一感測器，而不是一開始就重啟整個系統。
5. 若無線資料異常，檢查天線、遮蔽物、電源與部署位置。
6. 若懷疑硬體故障，再交叉測試其他開發板或更換感測器。
7. 使用三用電表的歐姆檔可協助判斷開路或短路。
8. GPIO 與 5V/3.3V 電壓相容性要特別注意，避免燒毀主板。

## 五、訊號處理與資料傳輸觀念

### 類比到數位轉換

感測器輸出常為連續類比訊號，若要交給 MCU 或電腦處理，通常需要：

```text
Sampling → Quantization → Coding
```

有些感測元件內建 ADC，可直接提供數位輸出；有些則需外接 ADC 或使用開發板內建 ADC 腳位。

### 資料量與邊緣運算

若大量感測器頻繁回傳原始資料，後端頻寬可能不足。較好的方法通常是：

- 在邊緣端先轉換成事件資料
- 只上傳必要變化或警示
- 降低不必要的 raw data 傳輸

這也是未來 IoT、ROS 2、智慧感測系統的重要設計思想。

## 八、Peter 的教學延伸方向

這份題庫很適合轉成「機械系學生的感測器工程入門」教材。建議不要只讓學生背答案，而是整理成三層能力：

1. **辨識能力**：知道每種感測器能量測什麼物理量。
2. **系統能力**：知道感測器如何接到 MCU、網路、雲端或 ROS 2 node。
3. **除錯能力**：知道讀值異常時如何從電源、接線、通訊、原始資料一步步查問題。

這會比單純考證照更接近真正的工程訓練。
